▶ Analizar directo

Pega la URL de tu directo (Twitch, Kick o YouTube). Primero se valida con POST /api/streams/validate y luego se crea la sesión con POST /api/streams. El estado en vivo es el que devuelve la API: sin credenciales de plataforma la API responde requires_credentials y así se muestra — nunca se inventa un «en vivo».

Para vídeos ya publicados (no en directo) usa Descargar por enlace o Subir vídeo propio: un enlace pegado aquí solo crea la sesión, no descarga ni procesa el vídeo.

    ⬆ Subir vídeo propio

    Subida directa a S3: el navegador sube el archivo directo al almacenamiento con una URL prefirmada (POST /api/videos/upload/presign → PUT directo → POST /api/videos/upload/complete), sin pasar por el proceso web. La subida clásica (multipart a POST /api/videos/upload) queda como reserva si la directa no está disponible. La API deduplica por SHA-256: si el archivo ya existe no hace falta subirlo otra vez. Límite: 2 GB (MAX_UPLOAD_GB).

      🔗 Descargar por enlace (YouTube)

      Pega el enlace de tu propio vídeo de YouTube y la página lo descarga y lo procesa, como OpusClip. Solo vídeos propios o autorizados. YouTube no entrega el vídeo por ninguna API oficial, así que la descarga usa yt-dlp; desde un servidor en la nube YouTube la bloquea sin sesión, por eso hacen falta tus cookies (abajo). Límite: 2 h de duración, 2 GB.

      Cookies de YouTube (necesarias para descargar)

      Sin estas cookies, YouTube responde «confirma que no eres un robot» y la descarga falla. Son tu sesión de Google: solo se usan para descargar tus vídeos y nunca se muestran ni se comparten. Caduca cada cierto tiempo: si una descarga falla con ese mensaje, vuelve a exportarlas.

      Cómo exportar tus cookies (una vez)
      1. En Chrome, instala la extensión Get cookies.txt LOCALLY.
      2. Abre youtube.com con tu sesión iniciada.
      3. Pulsa el icono de la extensión y exporta el archivo cookies.txt.
      4. Súbelo aquí abajo con el botón «Subir cookies».

          No disponible (no inventado)

          • Gasto GPU en tiempo real: no disponible — no existe endpoint ni libro de gasto (usage_ledger) en la API actual. En el camino 0 $ no hay GPU: el cómputo es CPU del host. Pendiente: registrar GPU-segundos por trabajo si algún día se usa GPU.
          • Horas procesadas / consumo de API por día: no disponible — la API no expone contadores de YouTube/Twitch/Groq. El panel muestra los límites, no un consumo inventado.
          • Gasto mensual en USD: 0 $ real en el camino 0 $ (host Render Free + Supabase dentro de 1 GB de almacenamiento + faster-whisper tiny en CPU). No hay factura que consultar: no existe integración verificada de facturación de ningún proveedor (PRESUPUESTO §5).
